# Exposure 1.9.18 for Minecraft 26.3 — Beta 1

> This is an unofficial Fabric port maintained by David-Floy. It is not an official release by Mortuusars, and port-specific issues must not be sent to the official Exposure tracker.

## Upstream and requirements

- Based on Exposure 1.9.18 by Mortuusars, fixed upstream commit `9383e0c9237099947a1e6399fcace5772f496c7d`.
- Continues the unofficial Minecraft 26.1.2 Fabric port by Filmorae.
- Minecraft 26.3.
- Java 25.
- Fabric Loader 0.19.5 or a compatible newer version.
- Fabric API 0.164.0+26.3 or a compatible newer 26.3 build.
- Forge Config API Port 26.3.1.

Install Fabric Loader and the required dependencies, then place the port JAR in the instance's `mods` directory. Back up worlds and Exposure data before testing.

## Verified functionality

- Automated: 70 migration tests (0 failures, 0 errors, 0 skipped), Common and Fabric compilation, both Access Widener validations, and the complete Gradle build, locally and in GitHub Actions from a fresh checkout.
- Development client on Windows 11 with an AMD Radeon RX 6750 XT, on the OpenGL and the Vulkan backend: startup, world creation and entry, background Capture with an exported photograph (full world frame including the sky, no HUD or hand), repeated captures on Vulkan, camera attachments on dropped and held cameras and in item frames, and clean exit. The maintainer's in-game tests on both backends found no further problems.
- Dedicated server: startup to `Done` with all Exposure advancements loaded, and a normal stop.
- Release JAR in a launcher instance with the required dependency versions: mod list entry, new world, photographs captured, developed and printed in the Lightroom, Album notes and signing including text input, photograph frames, export, save/reload, and clean exit.
- In the same launcher instance together with Iris 1.11.7+26.3-fabric, Sodium mc26.3-0.9.2-fabric, and Lithium mc26.3-0.26.2-fabric: no problems found (maintainer report; the Shader Pack and graphics API were not recorded).

## Rendering and Shader scope

Capture was verified without Shader Packs on OpenGL and Vulkan, with Improved Transparency off, and Iris 1.11.7+26.3-fabric, Sodium mc26.3-0.9.2-fabric, and Lithium mc26.3-0.26.2-fabric worked in the maintainer's launcher test. Improved Transparency, other versions of these mods, specific Shader Packs, other GPUs, player model layers, skin layers, and other rendering mods are unverified until tested with exact version evidence.

## Compatibility warning

Compatibility with older Exposure worlds, photographs, albums, exposure repositories, or other persisted data is not guaranteed. Use a backup and a test instance. The mod id remains `exposure`, but this does not imply cross-version data compatibility.

## Known issues and support boundary

- This prerelease supports Fabric only.
- Improved Transparency (order-independent transparency) has not been tested with this port.
- The "Keep Post Effect" capture option covers only the vanilla spectator post effect; post effects that 26.3 applies through `/posteffect` are not disabled for photographs.
- An occupied glass photograph frame replacing its front pane/highlight is fixed upstream behavior, not a port blocker.
- Optional integrations (JEI, Jade, Create, Easy Anvils) are not part of this build.

See `KNOWN_ISSUES.md` and `COMPATIBILITY.md` for the maintained matrix.

## Changes since the 26.1.2 port

- Ported to the Minecraft 26.3 rendering (Renderpearl, Vulkan backend, SPIR-V shaders), SDL3 input, GUI/HUD, level extraction, datapack, and predicate APIs.
- Background Capture follows the 26.3 frame lifecycle and includes the sky, without synchronous readback, an extra level render, or screen cropping.
- Loot tables and advancements use the 26.3 data formats; the lightroom recipe advancement requires developed film again.
- Camera attachments (flash, lens, viewfinder, selfie stick) are no longer misplaced on dropped and held cameras and in item frames (inherited from the 26.1.2 port).
- The JAR contains the MIT license text.
